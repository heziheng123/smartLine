# 独立专注计时：需求文档（MVP）

状态：MVP 已冻结
版本：0.7
范围：独立专注计时功能；专注主题只能由用户手动创建，本阶段不与项目规划项目、项目任务、每日安排、知识大盘或艾宾浩斯建立业务关联。

## 1. 背景与目标

用户需要按长期学习主题累计真实专注时间，例如“数学分析”“考研政治”“英语阅读”。这类投入不一定能、也不应该先被拆成项目任务或排入日程。

本功能提供一个独立的专注时间账户：用户先手动建立专注主题，再开始番茄钟或自由计时；结束后保存真实投入，并在当天、本周和主题维度查看进度。

### 成功标准

1. 用户可在三步内开始一次计时：打开专注 → 选择手动创建的专注主题 → 开始。
2. 每次结束后，专注主题的累计时长准确增加，且页面刷新、设备同步、备份恢复后记录仍存在。
3. 用户不需要创建任何项目规划项目、项目任务或日程，即可独立完成整个计时与统计流程。
4. 用户能在一周视图中判断各学习主题的实际投入是否符合目标。
5. 同一浏览器配置文件中，无论打开多少个工作区或标签页，都不会产生两条同时运行的活跃会话或重复的正式记录。

## 2. 产品边界

### 本期包含

- 手动创建的专注主题的创建、编辑、排序、归档与恢复。
- 番茄倒计时与自由正计时。
- 单一活跃计时器、暂停、恢复和结束。
- 可选记录打断原因与简短备注。
- 单次记录、当日/本周累计、主题累计和每周目标进度。
- 本地优先存储、完整备份和统一工作区同步。
- 基础键盘可访问性、移动端可操作性和页面刷新恢复。

### 本期明确不包含

- 与项目规划项目、Timeline 项目、智能任务、每日安排、复习轮次、知识节点的自动关联。
- 结束计时后自动完成任务、创建任务或写入每日复盘。
- 多个并行计时器、多人共用计时器或社交排行榜。
- 网站屏蔽、白名单、摄像头监控、复杂的习惯养成体系。
- 日历同步、系统级后台常驻与强制通知。

上述能力只有在独立计时的核心流程稳定、且用户明确需要时再评估。

## 3. 核心概念

| 概念 | 定义 | 示例 |
| --- | --- | --- |
| 专注主题 | 用户手动创建、可长期累计投入时间的分类；不引用也不创建项目规划中的项目。 | 数学分析、考研政治 |
| 专注会话 | 从开始到结束的一次计时记录，可包含若干暂停。 | 数学分析 50 分钟 |
| 活跃会话 | 当前浏览器配置文件内正在运行、暂停或等待恢复处理的一次会话。整个浏览器配置文件最多一条；不同设备互不限制。 | 正在做数学分析 |
| 番茄模式 | 有预设目标时长的倒计时。到点提示用户决定下一步。 | 25、50、90 分钟 |
| 自由模式 | 从零开始累计时长，不设结束时间。 | 午后阅读 |
| 周目标 | 用户为专注主题设置的每周有效专注分钟数；可不设置。 | 数学分析每周 600 分钟 |

## 4. 用户故事

1. 作为备考用户，我可以新建“数学分析”和“考研政治”，方便分别统计投入。
2. 作为正在学习的用户，我可以从手动创建的“数学分析”主题卡片直接开始 50 分钟番茄钟，不需要创建项目规划项目、任务或日程。
3. 作为被打断的用户，我可以暂停并记录原因，恢复后继续累计有效专注时间。
4. 作为结束学习的用户，我可以保存并结束、继续当前计时或放弃本次，而不会误改其他模块状态。
5. 作为复盘用户，我可以通过图标、进度环和趋势图看到今天和本周在各主题上的真实专注时间、会话次数和目标进度。
6. 作为跨设备用户，我可以在另一台设备看到已经结束的专注记录；不会因计时界面每秒刷新而产生同步冲突。

## 5. 功能需求

### 5.1 专注主题管理

- 用户只能手动创建专注主题；创建流程中不得出现或读取项目规划中的项目列表。
- 用户可以创建专注主题，必填名称；默认名称去除首尾空白后不能为空。
- 可选设置颜色、每周目标分钟数和默认后台策略。每周目标必须为 1–10080 的整数分钟；未设置目标时不显示进度压力或失败状态。
- 默认后台策略可选“后台持续计时”或“离开页面自动暂停”；未设置时默认“后台持续计时”。该值只用于初始化新会话，本次会话临时修改不得反向修改主题默认值。
- 主题按用户自定义顺序展示；可编辑名称、颜色、周目标。
- 归档主题不再出现在开始计时列表中，历史记录和统计仍保留；可恢复。
- 同名主题允许创建，不以标题作为数据身份。

### 5.2 开始专注

- 用户从专注主题卡片选择以下模式之一：自由计时、25 分钟、50 分钟、90 分钟；番茄模式的默认时长固定为 50 分钟。
- 允许输入 5–240 分钟之间、以 5 分钟为步长的自定义番茄时长。
- 开始会话时，先在本地持久化事务中创建活跃会话，并固定会话时区快照；只有事务成功后才进入 running UI 并显示紧凑的专注控制条。创建失败时不得显示已开始，必须提示失败并允许重试。
- 若已有活跃会话，开始入口必须直接打开当前会话；`recovery-needed` 会话必须进入恢复面板，其他会话用户只能恢复、结束或放弃，不能创建第二条“稍后继续”的挂起会话。
- 多标签页或多工作区并发开始时，必须通过 IndexedDB 原子读写事务或等价互斥机制保证整个浏览器配置文件最多一条活跃会话。活跃记录使用浏览器级固定互斥键 `active-focus-session`，不得以 `workspaceId` 或主题作为互斥范围；`BroadcastChannel` 仅用于刷新其他标签页 UI，不能作为唯一判断依据。
- 计时显示以真实时间差计算；页面渲染刷新不得改变累计数据。

### 5.3 暂停、恢复与结束

- 暂停时停止有效时间累计，并可选记录打断原因：临时事务、被他人打断、精力不足、切换任务、其他。
- 恢复后从暂停时长之外继续累计。
- 番茄倒计时归零后给出视觉提示；用户仍需主动选择结束或继续，不自动保存、不自动创建下一轮。
- 结束时显示收尾面板：有效专注时长、暂停次数、可选备注。
- 收尾面板只提供“保存并结束”“继续计时”“放弃本次”。“完成本次”“继续稍后做”“仅保存记录”等暗示任务状态或挂起会话的文案不得出现。
- 放弃必须二次确认；已保存的历史记录不应因“放弃”被误删。
- 有效时长少于 1 分钟的会话不能保存为正式记录。
- 番茄倒计时归零后进入“目标已完成”状态；若继续计时，显示“目标已完成 · 超时 +MM:SS”，不得停留在 `00:00`。
- 用户点击“保存并结束”后，只有正式会话写入及活跃会话清除的本地事务成功，才能关闭收尾面板并显示保存成功。若写入失败，必须保留活跃会话和收尾面板，显示失败原因并允许重试；不得删除活跃会话或假装保存成功。
- 若用户在 `paused` 状态下保存并结束，点击保存的时刻同时作为 `currentInterruption.endedAt`；该暂停区间写入正式 `interruptions`，但不计入 `activeSeconds`。

### 5.4 后台、关闭与计时准确性

网页可以可靠记录“计时器处于运行状态的真实经过时间”，但无法判断用户离开页面后是否仍在真实学习。因此，本功能必须区分**时间计算准确性**与**真实专注真实性**：前者由技术保证，后者由用户在后台策略和恢复确认中决定。

- 当前页面可见时，计时显示使用单调递增时钟与时间戳差值计算；不得以 `setInterval` 的执行次数累计秒数。
- 切换到后台、平板锁屏或浏览器节流后，UI 刷新可能暂停；回到前台时必须按时间戳重算，而不是少算或多算被节流的时间。
- 每个主题可选择默认后台策略：**后台持续计时**或**离开页面自动暂停**。默认采用“后台持续计时”，适合用户切到 PDF、电子书或笔记应用后继续学习；用户也可在每次会话开始前改选。
- 使用“离开页面自动暂停”时，`visibilitychange` 触发后立即记为暂停；重新可见时需由用户恢复，后台时长不计入。
- 活跃会话在开始、暂停、恢复及 `visibilitychange` 变为隐藏时，立即将恢复锚点写入本设备持久化存储；`pagehide` 作为补充机会，不能作为唯一依赖，更不能依赖每秒落库。
- 关闭标签页、浏览器被系统回收或设备重启后，重新打开应用必须检测到未结束会话。若最后持久化状态为 `running` 且运行连续性无法确认，默认连续计时并恢复运行；若最后持久化状态为 `paused`，直接恢复为暂停状态，已知暂停时段不计入。
- 对于正常触发关闭事件的情况，系统尽力保存最后可观察到的关闭时刻与最后可信锚点，但不依赖在关闭瞬间成功写入恢复状态。对于崩溃/强制终止导致没有关闭事件的情况，系统使用已有最后可信锚点，并将运行中的会话恢复为持续计时；最后持久化状态为 `paused` 时保持 `paused`。
- 同一页面生命周期内，同时比较单调时钟和系统时钟。若两者差异超过 60 秒，将会话标记为“时间异常待确认”，提示“设备时间可能变更”，要求用户确认后才保存异常会话。该比较是异常探测而非篡改检测；睡眠、锁屏或平台时钟差异也可能触发。
- 系统无法防止用户修改设备时间，也无法确认屏幕外的真实学习状态；这属于网页应用不可消除的边界，不能以“绝对真实专注时长”宣传。

### 5.5 记录与统计

- 每次保存生成一个以开始时确定的 `sessionId` 为 ID 的正式会话，包含所属主题、起止时间、有效时长、模式、目标时长、暂停摘要和备注。
- 用户可从历史记录列表或主题详情选择“添加记录”，手动补录过去的专注会话。补录必须选择已有主题、填写开始时间、结束时间和有效时长；可选填写模式、番茄目标、打断记录和备注。补录的默认模式为自由计时。
- 手动补录的时间按创建时的当前设备时区解释并固定为该会话的 `timeZone`；系统据此计算 `localDate`。结束时间不得晚于提交时刻，且补录数据必须满足本模块全部数据不变量。
- 补录提交时生成新的 `FocusSession.id` 和 `createdAt`，以 `source = 'manual'` 写入正式数据域；不得创建、替换或影响 `ActiveFocusSession`。持久化成功后才显示成功并计入统计、备份和同步；失败时保留表单并允许重试。
- 用户可通过历史记录的“编辑”操作更正已保存会话的所属主题、起止时间、有效时长、模式与目标时长、打断记录和备注；编辑必须使用明确的保存操作，不能由计时 UI 自动改写历史记录。
- 今日视图显示：总有效专注时长、会话数量、各主题占比。
- 本周视图显示：按主题的累计分钟数、每周目标进度和最近七天分布。
- 周目标未达成时仅展示进度，不发送提醒或推送。
- 主题详情显示：累计时长、本周时长、最近会话列表和周目标完成度。
- 历史编辑保留会话 `id`、`source`、`timeZone` 与 `createdAt`；编辑起止时间时，必须按固定 `timeZone` 重新计算 `localDate`。所有变更均须通过本模块的数据不变量校验，并更新 `updatedAt`。
- 已删除会话不可编辑或隐式恢复；需要恢复时只能使用未来明确提供的恢复已删除记录操作。
- 历史编辑只有在本地持久化事务成功后才显示成功并重算统计；写入失败时必须保留原记录和编辑表单，提示失败并允许重试。
- 删除已结束会话必须写入 `deletedAt` tombstone，而非物理删除；删除需确认，并立即重算统计。已删除会话不出现在默认记录列表和统计中，但应保留给同步、备份与冲突合并。
- 同一 `FocusSession` 的 `deletedAt` tombstone 合并优先于普通字段更新；来自其他设备的备注等普通更新不得清除 tombstone 或使会话复活。只有未来明确提供“恢复已删除记录”操作时，才能通过显式 undelete mutation 清除 tombstone。
- 历史统计只统计未删除的正式会话的有效专注时长，不把暂停时间计入。
- 今日、本周、主题累计等正式统计只基于已保存 `FocusSession`；`ActiveFocusSession` 仅在“当前专注”区域显示，不能暂时计入仪表盘或历史累计。

### 5.6 刷新、同步与备份

- `ActiveFocusSession` 必须保存在本设备持久化 IndexedDB 的 local-only 存储中，用于刷新、关闭、重启和系统回收后的恢复；不得使用仅限标签页生命周期的 `sessionStorage`，也不进入跨设备实时同步。
- `FocusSubject` 与已结束并保存的 `FocusSession` 均属于正式 Focus 数据域，使用既有 IndexedDB、可移植完整备份与统一工作区同步链路。
- `ActiveFocusSession` 仅是本机运行状态与恢复状态：不得进入可移植工作区备份或跨设备同步。每个浏览器配置文件最多一条；不同设备的活跃会话互不感知、允许并行。
- 活跃会话的 hydration、恢复、计时 UI tick 和 `visibilitychange` 不得产生正式会话数据或工作区同步 mutation。
- 同步先后到达 `FocusSubject` 和 `FocusSession` 时，不能因暂时找不到主题而丢弃会话；客户端必须保留会话，并在主题到达后解析名称。
- 导入旧备份时，缺少专注数据应被视为空数据，不能导致导入失败。
- 存在属于某工作区的 `ActiveFocusSession` 时，不允许删除、退出、清空或覆盖导入该工作区；用户必须先保存并结束或放弃当前专注，避免正式化时失去目标工作区或主题。

## 6. 页面与交互

### 6.1 专注首页

第一版将专注作为每日安排旁的独立面板提供，方便快速开始计时；其数据、状态与交互仍完全独立于每日安排和其他业务模块。

页面由四个区块组成：

1. **当前专注**：没有会话时展示最近使用主题和“开始专注”；有会话时展示主题名、倒计时/正计时、暂停、结束。
2. **我的专注主题**：主题卡片、周目标进度、累计时长及快捷开始按钮。
3. **今日投入**：今日总时长、会话数量和按主题分布。
4. **本周回顾**：七日趋势和主题目标进度。

桌面端的活跃会话控制条应在切换本应用其他视图后仍可见；移动端使用底部紧凑控制条。它不遮挡主要操作，并具有明确的暂停、结束和返回入口。当前会话不写入“今日投入”等正式统计，控制条需明确展示“进行中”。

### 6.2 收尾面板

结束后不弹出冗长表单。默认只显示：

- “本次已专注 50 分钟”；
- 一个可选备注输入框；
- 保存并结束、继续计时、放弃本次三个操作。

打断原因在暂停时采集；结束时仅汇总展示，不要求重复填写。

### 6.3 中断会话恢复

运行中的未结束会话在重新打开时默认连续计时，关闭期间的时长会自动计入；若不希望关闭期间计时，应在本次会话中选择“离开页面自动暂停”。

若恢复的是最后持久化状态为 `paused` 的会话，不显示上述未知时段四选一面板；控制条直接显示暂停状态，并提供“继续计时”“保存并结束”“放弃本次”。

### 6.4 数据可视化与图标

第一版使用现有图标库、CSS 和原生 SVG 绘制图表，不引入新的图表依赖。图表必须同时显示文本数值，不能仅靠颜色或图形传达信息。

| 区块 | 可视化 | 信息 | 图标语义 |
| --- | --- | --- | --- |
| 当前专注 | 大号时间环/倒计时环 | 已专注、目标剩余、运行或暂停状态 | 时钟、播放、暂停 |
| 今日投入 | 三个摘要指标 | 有效时长、会话数、打断数 | 时钟、圆点计数、闪电/暂停 |
| 主题卡片 | 周目标进度环 + 累计时长 | 例如 360/600 分钟、完成比例 | 目标、趋势、归档 |
| 今日分布 | 水平堆叠条 | 各主题占今日专注时间的比例 | 分层色块 + 主题名称 |
| 本周回顾 | 周一至周日柱状图 | 每天有效专注时长及主题构成 | 日历、柱状趋势 |
| 主题详情 | 最近 7 天迷你趋势线 | 该主题的连续投入变化 | 趋势上升/下降 |

状态颜色仅用于辅助：运行使用品牌强调色，暂停使用警示色，完成目标使用成功色；所有状态同时提供图标、文字和数值。

## 7. 数据与规则

正式数据需要独立于现有项目任务与日程，以免两套语义互相污染。

```ts
type FocusInterruptionReason =
  | 'urgent'
  | 'people'
  | 'energy'
  | 'switch-task'
  | 'other';

type FocusInterruptionSource = 'manual' | 'background';

type FocusBackgroundPolicy = 'continue' | 'auto-pause';

type ActiveFocusSessionState = 'running' | 'paused' | 'recovery-needed';

type FocusSessionSource = 'timer' | 'manual';

/** 用判别联合排除 free 携带目标时长、pomodoro 缺少目标时长的非法组合。 */
type FocusTiming =
  | {
      mode: 'free';
      targetMinutes?: never;
    }
  | {
      mode: 'pomodoro';
      targetMinutes: number;
    };

interface FocusSubject {
  id: string;
  name: string;
  color: string;
  weeklyTargetMinutes?: number;
  /** 未设置时为 continue；仅用于初始化新会话。 */
  defaultBackgroundPolicy?: FocusBackgroundPolicy;
  order: number;
  archivedAt?: string;
  createdAt: string;
  updatedAt: string;
}

interface FocusInterruption {
  startedAt: string;
  endedAt: string;
  source: FocusInterruptionSource;
  reason?: FocusInterruptionReason;
}

interface FocusSessionBase {
  id: string;
  /** timer 表示由 ActiveFocusSession 正式化，manual 表示用户手动补录。 */
  source: FocusSessionSource;
  subjectId: string;
  startedAt: string;
  endedAt: string;
  activeSeconds: number;
  interruptions: FocusInterruption[];
  note?: string;
  /** 保存时固定，历史统计不因以后切换时区而重排。 */
  localDate: string;
  timeZone: string;
  /** 逻辑删除标记；统计和默认列表必须忽略该记录。 */
  deletedAt?: string;
  createdAt: string;
  updatedAt: string;
}

type FocusSession = FocusSessionBase & FocusTiming;

interface ActiveFocusSessionBase {
  /** 浏览器配置文件范围唯一的固定互斥键：active-focus-session。 */
  storageKey: 'active-focus-session';
  sessionId: string;
  /** 用于把正式记录写回开始会话时所在的工作区，不参与活跃会话互斥。 */
  workspaceId: string;
  subjectId: string;
  startedAt: string;
  /** 开始会话时固定；正式化时用于计算 localDate，不能在恢复时重读当前设备时区。 */
  timeZone: string;
  accumulatedActiveMs: number;
  runningSince?: string;
  state: ActiveFocusSessionState;
  backgroundPolicy: FocusBackgroundPolicy;
  lastTrustedAt: string;
  interruptions: FocusInterruption[];
  /** 正在暂停的区间不进入正式 interruptions，恢复时才补全 endedAt。 */
  currentInterruption?: {
    startedAt: string;
    source: FocusInterruptionSource;
    reason?: FocusInterruptionReason;
  };
}

type ActiveFocusSession = ActiveFocusSessionBase & FocusTiming;
```

规则：

- `mode = 'free'` 时 `targetMinutes` 必须为空；`mode = 'pomodoro'` 时 `targetMinutes` 必须存在，且为 5–240 之间、以 5 为步长的整数。该不变量同时适用于 `ActiveFocusSession` 和 `FocusSession`。
- 运行阶段以毫秒累计。正式化时先精确汇总全部运行区间的毫秒，再一次性以 `Math.floor(totalActiveMs / 1000)` 得到整数 `activeSeconds`；不得分段取整。`59.999` 秒不能保存，`60.000` 秒可以保存。
- `activeSeconds` 为唯一统计依据。所有统计必须先按秒汇总，再在展示层统一格式化或四舍五入；不得把每条会话先四舍五入为分钟后再相加。
- 正式会话必须满足 `endedAt >= startedAt`、`activeSeconds >= 60`，且 `activeSeconds` 不得超过 `startedAt` 至 `endedAt` 的实际跨度。每条正式 interruption 必须满足 `startedAt < endedAt`、位于会话起止范围内且彼此不重叠。
- 正式化时 `FocusSession.timeZone` 必须继承 `ActiveFocusSession.timeZone`；`localDate` 由实际选择的 `endedAt` 按该固定时区计算。恢复会话时不得以当前设备时区重算历史归属。
- `FocusSession.source` 在创建后不可修改：仅由 `ActiveFocusSession` 正式化创建的记录为 `timer`，用户手动补录的记录为 `manual`。手动补录不得创建或改写活跃会话。
- 新建正式会话时必须引用当前工作区中存在的 `FocusSubject`；主题归档不影响旧会话。同步时若 `FocusSession` 先于主题到达，客户端必须保留会话，待主题到达后再解析名称。
- 周目标达成按精确秒数判断：`weeklyActiveSeconds >= weeklyTargetMinutes * 60`。目标环最多渲染至 100%，文字保留真实分钟数和百分比；周目标修改后，当周按新目标即时重算，不保留历史目标快照。
- 周从周一开始，以保存时固定的 `localDate` 和 `timeZone` 归属；历史会话不会因用户以后旅行或在另一时区打开应用而移动到另一日/周。
- 跨越午夜的会话按结束时的 `localDate` 全部归属到同一天；这是统计展示规则，不改变真实 `startedAt` / `endedAt`，未来可在统计层虚拟切片而不破坏原始数据。
- `FocusSession` 是已结束的正式历史；`ActiveFocusSession` 只用于当前设备的恢复，不参与可移植备份或跨设备同步。
- 活跃会话状态机如下：`running` 经用户暂停或自动暂停变为 `paused`；`paused` 经用户恢复变为 `running`。生命周期中断不会要求崩溃前完成状态转换：下次启动时，若最后持久化状态为 `running` 且连续性无法确认，派生为 `recovery-needed`；若最后持久化状态为 `paused`，仍保持 `paused`。`recovery-needed` 只能经恢复面板的四种处理之一解决，不能直接继续运行。`currentInterruption` 只表示尚未结束的暂停区间，不得与 `recovery-needed` 混用。
- 活跃会话每次可持久化的状态转换都会先写入本设备存储，成功后才更新成功 UI；每秒仅刷新界面，不持久化。若暂停、恢复或结束的写入失败，必须保留最近一次已持久化状态，提示失败并允许重试。因页面被终止而无法写入时，恢复流程必须采用已有最后可信锚点的保守处理。正式历史中的 interruption 必须全部具有 `endedAt`。
- 应用启动时整个浏览器配置文件只允许恢复一条 `ActiveFocusSession`；开始另一条前必须先处理当前会话。
- 活跃会话有效时长超过 12 小时时，保存前必须提示异常时长，但允许用户确认保存。
- `note` 限制为单行短注，最长 200 字符；长篇反思不属于本模块。
- 所有上述数据不变量必须在用户输入、本地 IndexedDB 事务写入、备份导入及同步数据落库前执行 schema validation；不合法数据不得写入或覆盖有效正式数据，并应进入既有错误处理或隔离流程。

## 8. 非功能需求

- 不新增第三方计时、图表或通知依赖；优先使用浏览器定时器、页面可见性 API、原生 SVG 和已有 React/Zustand 基础设施。
- 计时漂移不得依赖 `setInterval` 的次数。前台使用单调时钟辅助检测，跨后台/重启使用持久化时间戳恢复，并在两者明显不一致时请求用户确认。
- 所有按钮具备可访问名称；键盘可到达开始、暂停、恢复、结束和关闭操作。
- 颜色不得是主题唯一识别方式；主题名称与数值必须始终可读。
- 计时控制在 200% 缩放和手机视口下可操作。
- 所有已结束数据必须进入现有的备份、导入校验和同步保护流程。
- 活跃会话的创建必须在本地持久化事务中检查并占用固定唯一活跃记录；同一浏览器配置文件的并发创建只能有一个成功。
- `ActiveFocusSession` 正式化时，必须以 `sessionId` 作为 `FocusSession.id`，以 `source = 'timer'` 写入，并在同一 IndexedDB 事务中执行 insert-if-absent 和清除活跃会话：若 `FocusSession` 不存在，创建正式记录后删除活跃记录；若正式记录已存在，只删除残留活跃记录，绝不得在正式化流程中覆盖正式记录。重复提交、崩溃恢复和用户连点保存都不得生成重复记录或修改已保存的计时事实；用户后续通过显式历史编辑产生的合法修改不受此限制。
- 正式会话的逻辑删除、主题归档和会话编辑必须作为同步可合并的数据变更传播；不得通过未登记的本地物理删除绕过同步。
- 同步合并中，`FocusSession.deletedAt` tombstone 优先于普通字段的最后写入；普通更新不得隐式 undelete。所有写入路径都必须先执行 Focus 数据不变量校验。

### 8.1 技术可行性结论

该功能在现有 Web/PWA 架构中可行，但实现目标应定义为“准确记录用户确认的计时会话”，不能承诺网页能在所有操作系统状态下持续后台运行或自动识别真实学习。

| 场景 | 可行性 | 必要策略 |
| --- | --- | --- |
| 正常前台计时 | 完全可行 | 用时间戳差值计算，不按定时器回调次数累计。 |
| 切换浏览器标签或平板后台 | 可行 | 使用页面可见性事件保存锚点；根据用户选择持续计时或自动暂停。 |
| 后台被浏览器节流 | 可行 | 返回前台后重新计算，不要求后台定时器持续执行。 |
| 正常关闭标签页/浏览器 | 可恢复，但关闭事件不是可靠前提 | 以 `visibilitychange` 为主、`pagehide` 为补充保存中断锚点；下次打开默认续计。 |
| 浏览器崩溃、系统强杀、断电 | 可恢复但不能自动判定真实结束时间 | 使用最后可信锚点恢复，运行中的会话默认续计。 |
| 跨设备查看历史 | 可行 | 只同步已结束会话；活跃会话保留在本机。 |
| 完全防篡改的真实学习时长 | 不可行 | Web 无法阻止系统改时、设备离线或确认外的行为；产品不作此承诺。 |

现有应用已具备 IndexedDB、本地持久化、工作区同步、完整备份和 PWA 基础；持久化工具已经支持跨对象仓库的原子写入，统一同步也已有实体级 tombstone 模式。正式化流程还需在该事务能力上支持清除活跃记录，不能退化为两个独立异步写入。因此正式会话可以复用既有数据安全链路，活跃会话只需增加一个 local-only 的持久化记录和互斥键，无需引入服务端、原生应用或新的第三方依赖。该功能会新增数据域和工作区 schema 版本；旧客户端必须被版本门禁阻止写入新数据。

## 9. 验收标准

1. 手动新建“数学分析”，开始 25 分钟后暂停、恢复、结束并保存；主题累计和今日累计与有效时间一致，暂停不计入。
2. 倒计时到零不会自动结束会话或自动开始下一轮。
3. 刷新页面后可恢复本设备未结束会话，且累计时长基于真实时间计算。
4. 已保存会话刷新后仍存在；导出、导入后仍存在；启用统一工作区后另一设备可见。
5. 归档“考研政治”后不能再从快捷开始中选中它，但既有时长仍在历史统计中。
6. 删除一条历史会话后，今天、本周及主题累计立即正确重算；另一设备同步后该会话不得复活。
7. 不创建 Timeline 项目、每日任务、复习任务或知识节点时，专注功能仍可完整使用。
8. 切换后台后，若选“后台持续计时”，回到前台的时长按真实时间差更新；若选“离开页面自动暂停”，后台时间不计入。
9. 最后持久化状态为 `running` 的会话在页面隐藏、关闭或异常终止后重新打开应用，系统能恢复中断会话并展示最后可信锚点；对于不能观测到的离线时段，必须要求用户确认，不得静默计入。
10. 修改系统时钟使单调时间与系统时间相差超过 60 秒时，保存前必须出现异常确认提示。
11. 同一浏览器配置文件中，两个标签页同时开始计时，最多只能有一个创建成功；不同设备可以各自存在一条不互相同步的活跃会话。
12. 仪表盘在有记录时显示时间环、主题进度环、今日分布条和本周柱状图；每个图形均有对应文字和数值。
13. 同一 `sessionId` 连续提交两次保存，或在“正式写入成功、活跃记录尚未清除”后崩溃恢复，最终仅存在一条正式会话，且不再提示未结束会话。
14. 暂停期间的活跃会话可正确表示未结束的当前 interruption；保存为正式会话前，每条 interruption 均有 `endedAt`，并保留 `manual` 或 `background` 来源。
15. 多条 91 秒会话的总时长按秒求和后再格式化；周目标达成按秒而非显示分钟判断。
16. 未保存的活跃会话只在“当前专注”显示，不计入今日、本周、主题累计或图表；保存后才一次性进入正式统计。
17. 50 分钟番茄钟继续运行 12 分钟后，界面显示“目标已完成 · 超时 +12:00”或同等语义，正式记录仍保存 62 分钟有效时长。
18. 用户换时区后，旧会话仍按保存时的 `localDate` / `timeZone` 留在原统计日和周；跨午夜会话的真实起止时间不变，统计仍按结束日归属。
19. 有效时长超过 12 小时的会话保存前出现确认提示，但用户可以明确确认保存。
20. 新 schema 工作区已写入 `FocusSubject` 或 `FocusSession` 后，旧版本客户端打开该工作区不得上传旧 schema 快照、不得覆盖或删除 Focus 数据；客户端必须提示升级或进入只读状态。
21. 同一浏览器配置文件中，工作区 A 已有活跃会话时，工作区 B 不能开始第二条；活跃会话保留其 `workspaceId`，正式化后记录只写入工作区 A。
22. 未设置默认后台策略的主题以“后台持续计时”开始；主题默认值可初始化新会话策略；用户本次会话改选策略后，不改变主题默认值。
23. 模拟 IndexedDB 在开始、暂停、恢复及保存时写入失败：开始不得进入 running UI；其余操作必须保留最近一次已持久化状态并显示可重试错误；保存失败时活跃会话和收尾面板都必须保留。
24. 导出工作区备份后，在另一台设备导入：`FocusSubject` 与已保存 `FocusSession` 会恢复；`ActiveFocusSession` 不会导出、导入或导致旧计时器复活。
25. 一段或多段累计为 59.999 秒的会话不能保存；累计恰为 60.000 秒时可保存为 `activeSeconds = 60`；多段运行时间只在总和后取整。
26. 手动暂停或自动暂停后状态为 `paused`；`running` 会话关闭或异常终止后、在下次启动时连续性无法确认时派生为 `recovery-needed`，恢复面板处理前不得直接将其变为 `running`；`paused` 会话关闭或异常终止后仍恢复为 `paused`，不显示未知时段四选一面板。
27. 周目标只能保存 1–10080 的整数分钟；拒绝零、负数、小数、非数值及超上限输入。
28. 跨时区恢复会话并按最后可信时间结束时，正式记录的 `timeZone` 与开始时的 Active 时区快照一致，`localDate` 按该时区和选择的 `endedAt` 计算，不因恢复设备的当前时区改变。
29. `free` 会话不能写入 `targetMinutes`；`pomodoro` 会话缺少目标、目标不是 5–240 的 5 分钟步进整数时，不能通过创建、导入、同步或 IndexedDB 写入校验。
30. 导入、同步或本地写入的正式会话若出现结束早于开始、有效秒数少于 60 或大于实际跨度、暂停区间越界、倒置或重叠，必须被校验拒绝或隔离，不得污染统计。
31. 在暂停状态下保存并结束，会话结束时刻必须补为 `currentInterruption.endedAt` 并写入正式 interruptions；该区间不计入 `activeSeconds`。
32. 工作区存在对应 `ActiveFocusSession` 时，删除、退出、清空或覆盖导入该工作区必须被阻止，并提示先保存并结束或放弃；处理完活跃会话后才能继续该操作。
33. 设备 A 删除会话后，设备 B 离线修改其备注再同步，最终会话仍保持 deleted；普通更新不得清除 tombstone 或使会话复活。
34. 用户可编辑一条未删除历史会话的主题、起止时间、有效时长、模式与目标、打断记录和备注；保存后会话 `id`、`timeZone` 与 `createdAt` 不变，`updatedAt` 更新，统计按修改后的数据立即正确重算并同步到其他设备。
35. 编辑后的会话仍必须通过模式、目标时长、起止时间、有效秒数和打断区间的不变量校验；不合法编辑不得写入。编辑写入失败时，原记录不变，编辑表单保留并允许重试。
36. 已删除会话不可通过历史编辑修改或复活；编辑其他设备已删除会话的离线更新在同步后仍由 tombstone 优先处理。
37. 用户可手动补录一条过去的专注记录；补录后生成新 ID，`source = 'manual'`，立即进入统计、备份与同步，且不会创建或替换当前 `ActiveFocusSession`。
38. 手动补录默认使用自由计时；番茄目标、起止时间、有效时长与打断记录均须通过数据不变量校验。补录结束时间晚于提交时刻或写入失败时，不得创建正式记录；失败时表单保留并允许重试。
39. 手动补录在创建时固定设备时区；后续跨时区打开或编辑时，记录的 `timeZone` 与 `source` 不变，`localDate` 始终按该固定时区计算。

## 10. 后续候选项（非本期承诺）

- 可选将一次专注会话关联到既有项目任务。
- 浏览器通知、提示音与休息倒计时。
- 自动建议下一个专注主题。
- 标签、地点、设备维度的统计。
- 导出专注记录为 CSV。

## 11. 已确定的产品决策

1. 第一版作为每日安排旁的独立面板提供，方便快速开始计时；数据和交互保持独立。
2. 默认番茄时长固定为 50 分钟。
3. 周目标未达成时仅展示进度，不提供提醒或推送。
4. 结束会话备注保留为单行短注，最长 200 字符。
