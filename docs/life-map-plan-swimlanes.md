# 人生地图项目泳道设计与开发指南

## 1. 功能边界

人生地图把长期系统、项目和项目子阶段组织为“学习 / 工作 / 生活”三大类泳道。布局模块接管 `LifeSystem`、`LifeGoal.kind === 'plan'` 与 `LifeGoal.kind === 'phase'` 的展示位置，不改变以下内容的业务语义、日期或编辑方式：

- 历史目标数据（仅保留在底层，不进入任何 UI 布局）；
- 人生时期；
- 长期系统的打卡与编辑语义；
- 周期复盘；
- 关键日期、时期重点和便签；
- 今天线、时间刻度、缩放、聚焦和画布创建。

大类是稳定的展示框架，人生领域是可编辑的子类。长期系统和项目都归属人生领域，不直接保存大类 ID；大类由领域的 `planGroupId` 推导。因此修改领域归属会移动该领域下的系统、项目及子阶段，但不会改写任何日期。

## 2. 用户可见行为

### 2.1 固定三大类

| ID | 名称 | 代表色 | 默认位置 | 默认领域 |
|---|---|---|---|---|
| `learning` | 学习 | 蓝色 `#6366F1` | 时间轴上方 | 学习成长 |
| `work` | 工作 | 黄色 `#D8A72E` | 时间轴下方 | 职业发展 |
| `life` | 生活 | 绿色 `#10B981` | 时间轴下方 | 身体健康、财务生活、家庭关系、兴趣与精神，以及旧自建领域 |

三大类不可新增、删除或改名。用户可以把整组移到时间轴另一侧，位置会持久化并参与多端同步。

### 2.2 人生领域作为子类

每个 `LifeArea` 作为二级分类独占一行。规划概览按学习、工作、生活三组直接列出二级分类；每组可新增多个分类，也允许为空。二级分类可改名、改色、组内排序、跨组移动和隐藏。

隐藏二级分类会同时隐藏对应系统与项目行。被项目、子阶段、系统、时期重点、便签或领域关键日期引用时不能删除；无引用时允许删除组内最后一项，tombstone 保证刷新、同步和恢复不会自动补回。

### 2.3 固定标签栏

时间画布左侧保留 128px 标签栏，桌面和 390px 小屏使用同一宽度。标签栏使用 CSS `position: sticky`，不在 JavaScript 滚动热路径中写入 transform。外层透明，只在实际泳道组范围绘制背景与边界，不遮挡人生时期。过长二级分类名使用单行省略，不改变行高。

标签栏包含：

- 大类名称与整组换边按钮；
- 领域色点与领域名称；
- 大类 4px 代表色色条；
- 与画布容器一致的 5% 浅色背景。

### 2.4 项目专用筛选

“全部项目 / 学习 / 工作 / 生活”筛选控制泳道容器、二级分类行、长期系统、项目和项目子阶段。人生时期、关键日期、注解、便签、今天线和时间刻度不受影响。

筛选是会话状态：刷新页面后恢复“全部项目”，不会写入同步数据或备份。

## 3. 数据模型

完整定义位于 `src/lifeMap/types.ts`。

```ts
type LifeMapPlanGroupId = 'learning' | 'work' | 'life';

interface LifeMapPlanGroupPreference extends SyncMeta {
  id: LifeMapPlanGroupId;
  placement: 'above' | 'below';
  order: number;
}

interface LifeArea extends SyncMeta {
  // 既有字段省略
  planGroupId: LifeMapPlanGroupId;
}

interface LifeMapData {
  lifeMapAreas: LifeArea[];
  lifeMapPlanGroups: LifeMapPlanGroupPreference[];
  // 其他集合保持不变
}
```

主计划原有 `placement` 字段继续保留，以便读取旧数据和回滚诊断；新项目泳道不再使用该字段决定主计划或阶段的位置。阶段从父主计划继承领域、大类、侧边和轨道，即使旧阶段记录中的 `areaId` 不一致，展示仍以有效父计划为准。

## 4. schema 6 与迁移

完整工作区 schema 为 `6`。`workspaceSchema.ts` 是版本号的纯模块来源，备份、同步元数据和测试共同引用它。schema 5 引入三大类与领域映射；schema 6 增加全局关键日期和可选关系。

加载 schema 1–5 时：

1. 补齐固定的三条 `lifeMapPlanGroups`；
2. 为内置领域补齐确定性映射；
3. 无法识别或缺少映射的旧自建领域回退到 `life`；
4. 修复非法大类 ID、非法位置、重复项和缺失项；
5. 保留主计划旧 `placement`，不做不可逆删除；
6. 规范化全局关键日期与可选关系；
7. 输出统一的 schema 6 数据。

schema 大于 6 的备份或云端工作区继续被拒绝，防止旧客户端覆盖未来字段。

## 5. 纯布局模块

`src/lifeMap/planSwimlaneLayout.ts` 不依赖 React 或浏览器 DOM。输入为长期系统、项目、子阶段、领域、大类偏好、筛选值、画布结束日和 `dateToX`；输出为大类容器、领域行、条带位置以及上下占用高度。

### 5.1 包含结束日的区间

业务日期是包含结束日的闭区间。布局时转换为半开区间：

```text
[start, targetDate + 1 day)
```

例如 A 在 8 月 3 日结束，B 在 8 月 3 日开始，两者仍然重叠；B 从 8 月 4 日开始才可复用 A 的轨道。

### 5.2 最少轨道算法

每个人生领域分两次执行贪心分轨：系统先分轨，项目后分轨。项目的轨道编号整体加上系统轨道数，保证系统始终位于项目上方。每一类内部都遵循：

1. 按开始日期、结束日期和稳定 ID 排序；
2. 为计划寻找第一条 `lastEndExclusive <= start` 的轨道；
3. 找到则复用，否则新建；
4. 更新轨道的结束边界。

每类使用的轨道数等于该类在同一领域的最大并发数。不同领域互不争用轨道；系统和项目也不互相抢占，因此缩放、过滤或其他领域变化不会改变纵向身份。无结束日期的系统使用画布结束日作为显示边界，但不会写回数据。

### 5.3 子阶段继承

子阶段不独立分轨。布局先定位父项目，再复制父项目的：

- `groupId`；
- `areaId` 与 `rowId`；
- `placement`；
- `trackIndex`。

子阶段只重新计算自己的横向起止位置。没有有效父项目的悬空子阶段在数据归一化时被过滤，不进入布局。

### 5.4 动态时间轴

布局输出 `topHeight` 与 `bottomHeight`。画布将泳道占用加入原有注解、目标、里程碑和人生阶段的避让距离，再计算 `axisY`。整组换边后轴可以自适应移动；所有元素的日期坐标保持不变。

上方容器从 `axisY - gap - topHeight` 开始，下方容器从 `axisY + gap` 开始。相同侧的大类按固定顺序稳定排列。

## 6. 渲染与视觉状态

`LifeMapWorkspace` 提供领域、大类偏好和主计划实体；`LifeMapView` 负责会话筛选、纯布局调用和画布渲染。

- 大类：代表色 4px 色条与 5% 浅底，无粗边框；
- 未来计划：虚线描边与约 10% 色彩填充；
- 当前和过去计划：实线与约 22% 色彩填充；
- 项目在所有缩放级别保持 26px 的完整胶囊高度，不再复用旧版 8px 细轨样式；
- 过去时间区域：4.5% 灰蒙层；
- 长期系统使用同一领域行，永远排在项目轨道上方；
- 项目继续显示进度、完成、维护、未规划区间和选中状态；
- 子阶段继续使用密度标签和父项目关系；
- 年/月/周/日缩放只改变横向密度，不改变大类、领域、侧边或轨道。

复盘和其他非系统/项目/子阶段条带继续使用独立渲染链，只在纵向上避让分类泳道。

关键日期、里程碑、注解和便签的纵向避让必须以实际渲染的 `topHeight` / `bottomHeight` 为准，不能再以旧项目轨道数量为条件。卡片位于对应侧全部大类容器之外，日期引导线仍可穿过泳道连接时间轴，因此既不覆盖项目内容，也不丢失日期锚点。

## 7. 同步、离线队列和备份

`lifeMapPlanGroups` 位于 `LIFE_MAP_FIELDS`，因此自动进入：

- Zustand 持久化与 IndexedDB 主存储；
- Liveblocks storage mapping；
- 工作区变更日志与离线队列；
- 实体级三方合并；
- 完整 JSON 备份、压缩快照和恢复；
- 工作区变更检测。

三方合并以大类 ID 为实体键。不同设备修改不同大类时可以无冲突合并；同时修改同一大类的同一属性时保留冲突路径，沿用现有保护流程。

默认三条偏好不计入“用户已有独立人生规划”的判断，也不增加备份摘要中的人生规划条目数。

## 8. 测试与验收

领域测试覆盖：

- 默认映射、旧数据回退和非法配置修复；
- 包含结束日的重叠与次日复用；
- 长期系统优先占用顶部轨道、项目轨道整体下移；
- 最少轨道、不同领域独立分轨；
- 子阶段继承、筛选、同侧稳定排序；
- 大类偏好的实体级合并与冲突路径。

Playwright 同时在桌面与小屏 Chromium 验证：

- 固定栏宽度为 128px；
- 横向滚动后固定栏屏幕坐标不变；
- 390px 小屏仍保留完整标签栏；
- 整组换边、阶段跟随和刷新持久化；
- 项目筛选不删除画布级元素；
- 筛选刷新后回到“全部项目”；
- 原有编辑、维护、批量顺延、画布创建和缩放交互无回归。

常用命令：

```bash
npm run test:life-map
npm run test:sync
npm run test:system
npm run test:e2e -- tests/e2e/life-map.spec.ts
npm run lint
npm run check
npm run build
```

## 9. 扩展约束

- 不要允许用户创建第四个大类；新增分类需求应创建人生领域。
- 不要把筛选状态写入 `LifeMapData`。
- 不要恢复使用主计划 `placement` 控制新泳道。
- 不要让阶段独立选择侧边或轨道。
- 不要因泳道换边修改项目、目标、阶段或里程碑日期。
- 新增同步集合时必须同时更新 schema、归一化、队列字段类型、备份验证、标签和迁移文档。
- 修改轨道常量或固定栏宽度后，必须同步更新纯布局测试与桌面/小屏 E2E。

## 10. 故障排查

### 标签随横向滚动移动

检查 `handleScroll` 是否仍在同步 `--life-map-scroll-left`，以及 `.life-line__plan-label-rail` 是否使用该变量做 X 方向补偿。

### 子阶段出现在错误领域或侧边

确认子阶段的 `parentGoalId` 指向有效项目；展示继承父项目，不使用子阶段自己的旧领域信息决定泳道。

### 换边刷新后恢复默认

检查 `lifeMapPlanGroups` 是否存在于 IndexedDB/镜像、`LIFE_MAP_FIELDS`、Liveblocks storage mapping 和工作区写入日志中；不要只修改组件本地状态。

### 旧备份导入失败

确认版本为 1–6，且 schema 1–5 被列入受支持旧版本。高于 6 的备份必须由更新客户端加载，不应手工降低版本号。
