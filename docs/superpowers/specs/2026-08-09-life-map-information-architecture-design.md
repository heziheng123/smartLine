# 人生地图信息架构与创建流程重构设计

> 历史设计：已被 `2026-08-09-life-map-interface-simplification-design.md` 取代。本文仅保留当时决策记录，不代表当前 UI。

## 目标

人生地图只向用户暴露四个一级对象：目标、项目、长期系统、关键日期。项目子阶段只从项目上下文创建；人生时期、时期重点、便签、复盘和领域管理按使用场景收纳，不再与一级对象并列。

本设计保留学习/工作/生活泳道、128px 固定标签栏、26px 项目胶囊、关键日期独立层、同步与备份语义，并且不自动重写任何历史日期。长期系统进入对应领域泳道，先于项目分配轨道并始终显示在项目上方。

## 信息架构

- 顶部只保留当前核心目标、下一关键日期、搜索、添加、规划概览和视图设置。
- 全局添加菜单只显示目标、项目、长期系统和关键日期；已有项目时额外显示“给现有项目添加子阶段”上下文操作。
- 人生阶段统一改称“人生时期”，只在规划概览的结构设置中管理。
- 计划阶段统一改称“项目子阶段”，在项目编辑器、项目胶囊和全局上下文操作中创建。
- 领域主题、阶段说明和历史范围便签统一投影为“时期重点”；新建时期重点写入 `lifeMapFocuses`，旧记录继续写回原集合。
- 文字便签进入画布工具，周期复盘进入规划概览，批量平移和维护期进入项目操作。
- 自然语言快速输入移出添加菜单，进入搜索/命令入口。

## 创建规则

目标、项目和长期系统按“当前项目 → 当前泳道领域 → 当前具体领域筛选 → 该类型上次领域 → 第一个可见领域”解析默认分类。分类以可编辑标签显示，详细字段折叠在“更多设置”中。

关键日期默认全局，不要求领域；可以在更多设置中关联项目或领域。全局关键日期在全部人生和单领域范围中均可见，项目筛选不影响关键日期。

子阶段自动继承父项目的领域、颜色、泳道和维护状态。默认日期为父项目内第一段未被子阶段覆盖的完整区间；无空闲区间时禁止保存并给出明确说明。

## 数据与兼容

工作区 schema 升至 6：

- `LifeGoal.outcomeGoalId?: string` 允许项目可选关联一个结果目标；
- `LifeEvent.areaId?: string`，缺失表示全局关键日期；
- `LifeEvent.relatedPlanId?: string` 允许关键日期可选关联项目；
- 无效关系只清除关系字段，不删除主体；无效关键日期领域降级为全局；
- schema 1–5 自动升级，未来版本继续拒绝加载；
- 现有主题、重点和范围便签不做不可逆迁移。

## 验收

- 添加菜单只有四个一级对象，子阶段有项目内和全局上下文入口。
- 用户创建关键日期不需要先选择领域。
- 顶部不再常驻主题和生活节奏多行摘要。
- 规划概览可以访问长期系统、时期重点、复盘、人生时期、领域和画布工具。
- 旧主题可在时期重点列表和画布上显示、编辑和删除。
- 桌面与 390px 小屏均通过创建、筛选、固定栏、关键日期避让和键盘操作测试。
