# SmartLine 地图工作区 v2：实施基线

## 目标

将思维导图和人生地图融合为同一张无限画布。画布可同时包含思维节点、人生对象、项目引用卡片和 Timeline Section；项目规划仍是项目数据的唯一来源。

## 不变约束

- Week Matrix、Daily、Knowledge Dashboard、EBB 不改业务模型。
- Map Workspace 不持久化项目标题、日期、进度或状态的副本，只保存稳定引用和画布布局。
- Timeline 是画布对象，不是独立的甘特页面；移动和缩放 Timeline 不改变其日期范围。
- 删除引用卡片或 Timeline 只删除画布对象，不删除项目数据。
- 不把业务实体统一为 MapNode。

## 以现有仓库为准的模型映射

| 产品概念 | 当前正式模型 | 备注 |
| --- | --- | --- |
| 项目 | `Task` | `tasks` 是权威集合；`groups.children` 是兼容投影。 |
| 项目分组 | `TaskGroup` | 只负责项目的视觉分组，不是项目本身。 |
| 项目任务 | `SmartTaskBlock` | 稳定引用使用项目 ID 与 Block ID 组成的现有 source ID。 |
| 项目阶段 | 暂无独立实体 | 后续仅在已有模型支持后添加，不虚构 `Stage`。 |
| 项目关键日期 | `Milestone` | 属于项目时间线 Store。 |
| 人生规划 | `LifeMapData` | 已含领域、阶段、主题、目标、系统、事件、笔记与复盘。 |

## 工作包与交付门槛

### WP0：项目访问边界

建立 `projectPlanningAdapter`，使新的地图工作区和现有 Life Map 均不直接依赖 Project Store。

- 暴露项目、项目内任务、里程碑读取和项目日期更新。
- 仅使用当前真实数据模型；不提供不存在的 `Stage` 或数值 `progress` 写入接口。
- 完成后现有 Life Map 投影行为必须不变。

### WP1：异构画布基础设施

将 Mind Map 从仅 `nodes / edges / sections / groups` 扩展为可注册的画布对象层。

- 定义共享几何边界与独立对象集合，例如 `projectReferences`、`timelineSections`。
- 同步、撤销重做、持久化、导入导出、空间索引和可视裁剪同时支持新对象。
- 不把 Timeline 或项目引用伪装为文本节点。

### WP2：只读项目引用卡

- 画布只存 `targetType`、`targetId`、布局和显示偏好。
- 渲染时由 Adapter 获取当前项目数据。
- 项目更新后自动刷新；删除卡片不影响项目。

### WP3：Timeline Section

- 支持项目、人生规划和持久化的手动混合引用来源。
- 建立不持久化的 `TimelineProjectionItem`。
- 首版仅长期、月、周三种尺度，并完成画布视口和 Timeline 行的双层裁剪。

### WP4：人生地图迁移

- 先构建可重复、可审计、可回退的迁移。
- 保留 Life Map 的完整实体语义，而非仅迁移阶段、事件和系统。
- 迁移验证后再关闭旧写入口；过渡期保持只读回退路径。

### WP5：双向编辑与语义缩放

- 拖动项目任务 Bar 通过 Adapter 修改权威任务日期。
- 画布移动/缩放不修改日期。
- 明确跨 Map Workspace 与项目 Store 的撤销、同步冲突和失败恢复策略后才开放写入。
- 完成 Compact / Expanded 与 LOD（<35%、35–70%、>70%）。

## 验收顺序

每个工作包完成后依次验证：类型检查、对应单元测试、现有页面回归；WP4 额外验证迁移幂等、旧数据备份与同步场景。任何一项失败，不进入下一个工作包。

## 人生规划正式写入口

地图文档现在直接拥有并编辑完整 `LifeMapData`，不再依赖旧 Life Store 作为日常写入口。

- 「人生规划」面板支持领域、阶段、主题、目标、长期系统、关键日期、时期重点、批注和复盘的创建、编辑与软删除。
- 长期系统支持当天完成次数记录；人生分组支持上下布局调整。
- 所有写入进入 Map Workspace 的历史、持久化、导入导出和同步链路。
- Life Timeline 直接读取地图文档内数据；拖动或缩放人生时间条修改同一份正式日期数据，并可用地图撤销恢复。
- 旧 Life Store 只用于一次性迁移、备份与显式恢复；恢复会明确提示覆盖当前地图内人生规划。

## 已验证

- `npm run test:planning`：项目适配器与引用投影测试通过。
- `npm run test:mind-map`：异构对象历史/同步和 Timeline 投影测试通过。
- `npm run build`：TypeScript 与生产构建通过。
- 浏览器回归：项目引用与 Timeline 可同时出现；切换项目来源无页面错误；Resize 从 `720×360` 到 `820×440` 后项目日期保持不变。
- Playwright 双端回归：项目任务 Bar 平移更新正式 `SmartTaskBlock.header.date/deadline`；撤销恢复原日期；结束边缘只修改截止日。
- Playwright 双端闭环：地图内人生阶段可创建和编辑；Life Bar 拖动更新正式 Map 数据并可撤销；手动 Timeline 可混合项目任务与人生对象；刷新后人生数据和手动选择均保持。

## Life Map 迁移阻断条件

关闭旧 Life Map 写入口前，迁移必须逐项覆盖 `LifeMapData` 的全部正式集合，而不只处理阶段、事件和系统；同时必须保留原始数据备份、迁移报告、幂等标识和只读回退入口。任一集合未覆盖时只允许预检，不执行所有权切换。

当前迁移会把 11 个集合完整嵌入 Map 文档；领域、专注和批注另生成稳定 ID 的轻量画布投影。迁移前自动下载 JSON 备份，同一指纹不会重复生成对象，源数据变化时会更新或清理对应投影。真实数据已验证，主导航已合并为「地图工作区」；旧 Life Store 不再提供独立写入口，但继续作为迁移读取与恢复来源。
