# 人生地图信息架构、二级分类与性能设计

## 1. 面向用户的对象

人生地图不再提供“目标”的创建、展示、搜索、编辑、关联或核心目标摘要。用户可新建的主要内容为：

| 内容 | 用途 | 最少字段 |
| --- | --- | --- |
| 项目 | 一段时间内要推进的事情 | 名称、开始日期、结束日期 |
| 长期系统 | 按日、周或月持续保持的规律 | 名称、频率、开始日期 |
| 关键日期 | 不能忽略的单日事实 | 名称、日期 |
| 时期重点 | 某个时间范围的整体背景说明 | 名称、开始日期、结束日期 |
| 文字便签 | 某一天的简短备注 | 内容、日期 |

项目子阶段是项目的内部能力，不是与项目并列的数据类型。人生时期、二级分类、复盘和批量日期调整属于规划概览中的低频管理能力。

## 2. 顶部与添加入口

顶部工具栏保留领域筛选、今天、缩放、搜索、添加、下一关键日期、规划概览和视图设置。旧“核心目标 / 下一关键日期”摘要行已删除；下一关键日期是工具栏内的紧凑按钮，有数据时显示名称和倒计时并可定位，无数据时显示“暂无关键日期”且禁用。

“添加”是单列菜单，顺序固定：

1. 新建项目；
2. 新建长期系统；
3. 新建关键日期；
4. 添加时期重点；
5. 添加文字便签；
6. 存在项目时，在分隔线后显示“给现有项目添加子阶段”。

时期重点进入画布范围选择工具；文字便签进入单日点选工具。视图设置和规划概览不再重复提供创建入口。

## 3. 固定一级分类与可编辑二级分类

一级分类只有学习、工作、生活，顺序固定，不可新增、删除或改名。`LifeArea` 正式作为二级分类：用户可在任一组内创建“考研”“期末考试”“主项目”“家庭关系”等内容。

二级分类可改名、改色、组内排序、移动到另一一级分类、隐藏和删除。排序由“固定一级顺序 + 组内 `order` + 稳定 ID”决定。一级分类可以为空，仍显示组标题、空状态和“添加二级分类”。

删除使用 tombstone，已删除的内置二级分类不会在刷新、同步或备份恢复后自动补回。若分类被项目、子阶段、长期系统、时期重点、便签或领域关键日期引用，删除按钮禁用，必须先迁移内容。

新建二级分类自动使用所属组的协调色板。项目或长期系统创建时优先继承当前项目、当前二级分类、当前筛选、本机上次选择，最后回退到第一个可见分类。三组都为空时禁用保存，并提供“先创建二级分类”直达入口。关键日期默认全局，不执行该分类规则。

## 4. 泳道与项目子阶段

每个二级分类独占一行。行内首先为长期系统分配最少轨道，再为项目分配轨道，因此长期系统始终在所属分类的最上方。项目区间使用包含结束日的日期语义；子阶段继承父项目的分类、大类、颜色、上下侧、轨道和维护状态。

子阶段可从项目编辑器、项目胶囊和全局上下文入口创建。日期必须在父项目内且不能互相重叠；编辑器默认选择第一段完整空闲区间。有子阶段时项目进度取子阶段平均值，否则使用项目手动进度。

左侧 128px 分类栏在桌面和 390px 小屏都使用 CSS `position: sticky`。其外层透明，只在实际学习/工作/生活容器范围绘制背景和边界，不再遮挡上方人生时期的标题、日期、当前标记和编辑按钮。

## 5. 关键日期、时期重点与文字便签

关键日期是独立画布层，默认全局，在任何二级分类或项目筛选下仍可见。更多设置可选关联项目、二级分类或自定义颜色。颜色优先级为自定义色、关联项目色、关联分类色、默认橙色。

时期重点不计算进度，不是项目，只回答“这段时间整体以什么为重点”，例如“9—12 月考研冲刺，减少社交并集中刷题”。历史 `LifeTheme`、`LifeFocus` 和范围便签通过 `LifeMapPeriodFocus` 统一投影，不复制或删除历史数据。文字便签则用于某一天的短说明。两者创建后均可在画布上直接点击编辑，也可通过搜索定位。

## 6. 规划概览

规划概览保留进行中项目、长期系统、复盘、人生时期、分组化结构设置和项目日期调整。它不再显示目标、时期重点列表或“画布工具”创建区。桌面端为右侧抽屉，小屏为全屏底部面板，支持 Escape 关闭、Tab 焦点循环和关闭后焦点返回。

## 7. 滚动性能边界

滚动热路径不允许遍历所有项目条写入内联样式，也不允许每帧向画布写入可继承的滚动 CSS 变量。分类栏、项目标签、人生时期标题和负载标签使用原生 sticky。小地图关闭时滚动不执行逐帧 DOM 写入；开启时只更新小地图视口的单个 transform。

项目/子阶段父子关系、领域日期范围和领域统计通过 `Map` 一次聚合，避免渲染期重复嵌套 `filter/find`。水平虚拟化保留稳定 overscan；滚动期间不提交主画布 React 视口状态，停止后最多统一提交一次。

## 8. 历史目标和 schema 6 兼容

底层 `LifeGoal`、`kind: 'goal'`、Store 操作、同步和备份字段继续保留，因为项目与子阶段仍共用该集合，且历史数据不得破坏性删除。所有 UI 投影必须明确只接受 `kind === 'plan' | 'phase'`；历史目标不得影响画布范围、搜索、统计、空状态、规划概览或新复盘快照。旧复盘快照中的目标数据保留，但不显示。

工作区 schema 保持 `6`，不执行破坏性迁移，不修改任何现有项目、子阶段、长期系统、人生时期或关键日期的日期。schema 1—5 仍自动升级，高于 6 的数据仍拒绝加载。

## 9. 验收要点

- 任何可见菜单、画布、搜索、编辑器和规划概览均无目标实体入口或展示；
- 添加菜单为单列五项，有项目时增加子阶段上下文项；
- 学习/工作/生活三组恒存，各组可为空并可独立管理多个二级分类；
- 长期系统在所属分类轨道最上方，项目子阶段继承父项目；
- 128px 分类栏不遮挡人生时期，横向滚动时标签不移动；
- 小地图关闭时，连续滚动不产生画布逐帧内联样式写入；
- 全局关键日期不受二级分类或项目筛选影响；
- 分类 tombstone、schema 6 备份、离线队列和实体级合并保持兼容。
