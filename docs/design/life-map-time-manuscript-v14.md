# v14「Life Manuscript 2.1 / 人生时间手稿」实施方案

> 状态：设计冻结候选稿  
> 目标：以“时间手稿 2.1”替换当前 Adaptive Life Path 路线图，同时保留旧视图作为一个发布周期的回退入口。  
> 核心原则：整个主视图只允许纵向表示时间；横向只表示分类、并行轨道和批注防重叠位置。

## 1. 最终产品目标

用户打开人生地图后，可以同时看懂：

1. 当前处于什么人生阶段。
2. 学习、工作、生活等分类中分别进行着什么。
3. 考研政治、英语、专业课等子项目从哪天开始、到哪天结束。
4. 今天有哪些项目正在进行。
5. 某一天发生了什么。
6. 某几天整体状态如何。
7. 多条日期批注发生重叠时分别属于哪个日期范围。

最终界面分为四个固定区域：

```text
顶部工具栏
──────────────────────────────────────────
日期刻度 │ 分类与项目画布               │ 批注栏
         │ 学习 │ 工作 │ 生活            │ 大括号＋文字
         │      │      │                 │
         │      ── Today ──              │
```

## 2. 冻结产品语义

开发前必须固定不同实体的职责，避免以后再次把所有内容画成同一种色带。

### 2.1 分类

分类是长期稳定的信息架构，不代表日期。

推荐保留三大类：

- 学习
- 工作
- 生活

现有 `LifeArea` 作为二级分类，例如：

```text
学习
├─ 学习成长
├─ 考研
└─ 语言学习

工作
├─ 职业发展
├─ 产品研发
└─ 创业

生活
├─ 身体健康
├─ 家庭关系
├─ 财务生活
└─ 兴趣与精神
```

第一版主画布只固定显示三大类，避免七八个栏目把画布挤得不可读。点击分类标题后，可以筛选或展开二级分类。

### 2.2 阶段

阶段是跨越一段时间的人生叙事背景，例如：

- 考研备考与生活平衡期
- 创业探索期
- 海外生活
- 健康恢复期

阶段不属于单一分类，可以同时覆盖学习、工作和生活。

阶段回答的是：这段时期整体是什么状态？

### 2.3 项目

项目属于某个分类，并且拥有开始和结束日期，例如：

```text
学习
└─ 考研备考

工作
└─ 项目收尾

生活
├─ 睡眠调整
└─ 每日运动
```

项目回答的是：这段时间具体在推进什么？

### 2.4 项目单元

项目内部允许两种子内容：

- 阶段型：先后发生，例如基础期、强化期、冲刺期。
- 并行型：同时发生，例如政治、英语、专业课。

示例：

```text
考研备考
├─ 政治      并行型
├─ 英语      并行型
├─ 专业课    并行型
└─ 冲刺阶段  阶段型
```

### 2.5 批注

批注是个人叙事内容：

- 单日批注：只关联一天。
- 区间批注：关联连续几天。
- 可以关联阶段、分类、项目或项目单元。
- 也可以保持为全局人生记录。

批注回答的是：这一天或这几天发生了什么、感受如何？

### 2.6 事件

事件只表示一个准确日期，例如：

- 六级成绩公布
- 考试
- 毕业
- 搬家
- 入职

事件不替代批注。事件记录“发生了什么”，批注记录“我如何理解这件事”。

## 3. 数据模型调整

主要影响 `src/lifeMap/types.ts`。

### 3.1 Stage 扩展

建议为 `LifeMapStage` 增加：

```ts
areaIds?: string[]
```

规则：

- 缺失或空数组：阶段跨越所有分类。
- 指定分类：阶段背景只覆盖关联分类。
- 阶段删除仍然只写 `deletedAt`。
- 删除阶段不删除项目和批注。

### 3.2 项目单元类型

现有 `LifeGoal.kind='phase'` 可以继续复用，但增加：

```ts
childRole?: 'phase' | 'track'
```

含义：

- `phase`：先后阶段。
- `track`：政治、英语等并行方向。
- 老数据缺失时默认 `phase`。

这样无需破坏现有 `plan + phase` 数据结构。

### 3.3 批注扩展

现有 `LifeMapNote` 应升级为真正的时间批注：

```ts
interface LifeMapNote {
  id: string
  name: string
  body?: string

  date: string
  endDate?: string
  type: 'pin' | 'range'

  areaId?: string
  relatedStageId?: string
  relatedGoalId?: string

  color?: string
  mood?: string
  importance?: 'normal' | 'important'

  createdAt: string
  updatedAt: string
  revision: number
  deletedAt?: string
}
```

其中：

- `name`：简短标题。
- `body`：一至多段正文。
- `areaId` 改为可选，允许全局批注。
- `relatedGoalId` 可以指向项目或项目单元。
- `layoutLane` 不再作为权威数据，轨道应实时计算。
- 旧 `placement`、`layoutLane` 仅保留兼容，不再由新视图写入。

### 3.4 数据迁移

旧数据迁移规则：

- 旧单日便签继续作为 `pin`。
- 旧范围便签继续作为 `range`。
- 旧 `name` 保留为标题。
- `body` 默认空字符串。
- 旧 `areaId` 保留。
- 旧阶段、项目、事件不需要复制。
- 不执行破坏性迁移。

验收：

- 旧备份可以直接导入。
- 本地存储、Liveblocks、导入导出不会丢字段。
- 多端编辑批注正文可以正常进行实体级合并。

## 4. 唯一纵向时间系统

现有 `src/lifeMap/time/lifeMapTime.ts` 可以继续作为基础，但需要统一所有实体的日期规则。

### 4.1 时间坐标

统一使用：

```ts
dateToWorldY(date)
worldYToDate(worldY)
```

所有内容必须使用同一个 Mapper：

- 阶段顶部和底部
- 项目顶部和底部
- 项目单元顶部和底部
- 系统
- Event
- Today
- 大括号顶部和底部
- 批注正文锚点

任何组件不得自行计算日期位置。

### 4.2 含首尾日期

日期区间统一采用含首尾规则。

```ts
topY = dateToWorldY(start)
bottomY = dateToWorldY(addDays(end, 1))
height = bottomY - topY
```

这样 `08-18—08-18` 仍然占据完整一天，不会变成零高度。

### 4.3 坐标含义

| 方向或属性 | 含义 |
|---|---|
| Y 坐标 | 真实日期 |
| 纵向高度 | 持续时间 |
| X 坐标 | 分类或防重叠轨道 |
| 颜色 | 实体类型或所属分类 |
| 透明度 | 视觉层级 |
| 边框强度 | 选中、当前、重要性 |

禁止：

- 横向长度表示时间。
- 使用横向进度条暗示日期。
- 因标签碰撞改变实体真实 Y 坐标。
- 为了美观缩短或拉长项目区间。

### 4.4 主视图日期范围

v14 范围应由以下内容共同决定：

- Today
- 活跃 Stage
- 活跃 Event
- 活跃 Project
- 活跃 Annotation

系统没有结束日期时，不允许无限拉长范围，只延伸到 Today 后默认缓冲区。前后各增加 60–90 天留白。

## 6. 阶段背景设计

阶段不再画成路径或粗色带，而是跨分类的浅色时间框。

### 6.1 基础样式

普通阶段：

- 背景透明度 3%–5%。
- 1px 柔和边框。
- 标题位于顶部。
- 日期位于标题下方。
- 不使用阴影或大卡片效果。

重要阶段：

- 边框稍深。
- 标题字号增加一级。
- 左侧增加 3px 强调边。

当前阶段：

- Today 所在阶段的标题高亮。
- 不通过扩大几何范围突出。

选中阶段：

- 边框和标题加深。
- 打开右侧阶段工作台。

### 6.2 阶段重叠

最多直接表现三个重叠阶段，排序优先级为：

1. 当前选中
2. 包含 Today
3. 重要阶段
4. 持续时间
5. 稳定 ID

重叠方式：

- 最底层阶段使用极浅填充。
- 第二阶段只显示边框和顶部标签。
- 第三阶段显示不同的内缩边框。
- 超过三条显示 `+N 个重叠阶段`。

禁止叠加多个高透明度颜色，避免变成污浊混色。

## 7. 分类栏目

默认显示：

```text
学习 | 工作 | 生活
```

每个项目通过 `LifeArea.planGroupId` 进入对应大类。

栏目顶部可以显示：

```text
学习
学习成长 · 考研 · 语言
```

交互：

- 点击“学习”只显示学习相关内容。
- 点击具体二级分类进一步筛选。
- 默认显示三大类全局视图。
- 分类顺序复用现有偏好设置。

第一版不允许任意增加十几个主栏目；过多栏目应成为二级分类。

## 8. 项目与项目单元轨道

### 8.1 项目表现

项目是栏目中的纵向区域。

```text
学习栏目

政治       英语       专业课
08-18      08-20      08-23
  │          │          │
  │          │          │
08-27      09-05      09-08
```

视觉要求：

- 顶部严格对应开始日期。
- 底部严格对应结束日期之后一天。
- 名称位于项目带顶部。
- 开始日期位于顶部小字。
- 结束日期位于底部小字。
- Today 横线穿过当前活跃项目。

### 8.2 项目层级

父项目“考研备考”显示为栏目内的弱边框项目组。政治、英语、专业课显示为其中的并行轨道。

父项目不应再覆盖一层浓色背景，只需要：

- 项目标题。
- 细边框范围。
- 项目统计。
- 子项目轨道。

### 8.3 分轨算法

每个分类独立计算轨道。

规则：

1. 按开始日期、结束日期、稳定 ID 排序。
2. 区间采用含首尾日期。
3. 如果上一个项目结束日期早于下一个项目开始日期，轨道可以复用。
4. 有日期交集时必须进入新轨道。
5. 父项目内的子项目单独分轨。
6. 轨道顺序不能因滚动或选择发生变化。

第一版每个栏目最多展示四条并行轨道。

超过四条：

```text
政治 | 英语 | 专业课 | +3
```

点击 `+3` 展开完整列表或进入阶段工作台。

### 8.4 进度表现

进度不得使用横向长度或纵向高度表示。

推荐使用：

- `65%` 文字。
- 小型环形进度。
- `进行中 / 暂停 / 完成` 状态标签。
- 颜色明度变化。

项目的纵向长度永远只表示时间。

## 9. 系统与打卡

长期系统不能和项目使用完全相同的实体形态。

建议：

- 系统显示为更细的点状纵向轨道。
- 系统名称位于顶部。
- Check-in 显示为对应日期上的小圆点。
- 连续打卡可以形成稀疏点列。
- 同一天多个记录聚合为 `● N`。
- 年/月视图只显示活跃系统数量。
- 周/日视图展开实际打卡。

```text
每日运动
● 08-21
● 08-22
● 08-23 · 2
```

## 10. 批注大括号系统

这是 v14 的核心新增能力。

建议新增纯逻辑模块：

```text
src/lifeMap/geometry/
├── annotationIntervalLayout.ts
├── annotationBraceGeometry.ts
└── annotationTextCollision.ts
```

### 10.1 单日批注

单日批注显示为：

```text
● 08-24
收到六级成绩，比预期更好。
```

单日标记的 Y 坐标严格等于日期中心。

### 10.2 区间批注

```text
08-18 ┐
      │
08-21 ┘  连续几天状态很好……
```

大括号顶部和底部必须精确对齐日期区间。正文默认与大括号中点对齐。

### 10.3 重叠算法

所有批注先转为含首尾的日期区间，然后采用最少轨道分配。

排序：

```text
start ASC
→ end ASC
→ importance DESC
→ id ASC
```

轨道复用条件：

```text
previous.end < next.start
```

同一天仍然算重叠。

### 10.4 部分重叠

例如：

```text
A：08-18—08-21
B：08-20—08-24
```

分别进入轨道 1 和轨道 2。大括号横向并列，但顶部和底部仍由统一纵向时间确定。

### 10.5 包含关系

例如：

```text
A：08-18—08-25
B：08-20—08-22
```

A 使用外侧轨道，B 使用内侧轨道，形成可读的嵌套关系。

### 10.6 完全相同日期

相同日期范围优先合并：

```text
08-18—08-21 · 3 条批注
```

展开后显示全部正文。

### 10.7 轨道上限

桌面最多显示三条大括号轨道。超过三条：

```text
+4 条批注
```

点击后弹出日期范围内的完整列表。

### 10.8 正文碰撞

大括号位置不能移动，但正文可以适度避让。

规则：

1. 大括号严格保持真实日期。
2. 正文优先对齐大括号中点。
3. 与上一正文重叠时向下避让。
4. 增加短连接线表示原始锚点。
5. 避让超过 80px 时折叠为标题摘要。
6. 点击后展开全文。

### 10.9 关联标签

批注可以显示小型关联标签：

```text
英语
考研备考
生活
```

关联标签只用于说明，不决定批注颜色。

## 11. Today 与事件

### Today

Today 固定在最高视觉层级：

- 横穿日期刻度、所有分类和批注边界。
- 显示 `今天 · 08-21`。
- 使用单一强调色。
- 不遮挡文字。
- 页面打开默认将 Today 放在视口高度约 42% 位置。

### Event

Event 使用菱形节点：

```text
◆ 六级成绩公布
```

事件日期必须与左侧日期刻度严格对齐。

同一天多个事件：

```text
◆ 六级成绩公布 · +2
```

## 12. 缩放语义

保留年、月、周、日四种缩放，但每种缩放不仅改变像素密度，也改变信息量。

| 缩放 | 主要展示 |
|---|---|
| 年 | Stage、重要 Event、每月批注数量 |
| 月 | Stage、Project、重要 Annotation 摘要 |
| 周 | Project Track、系统、完整大括号 |
| 日 | 全部项目单元、Check-in、完整正文 |

建议像素密度：

```ts
year: 0.7 px/day
month: 4 px/day
week: 14 px/day
day: 32 px/day
```

切换缩放时：

- 以视口中心日期为锚点。
- 不允许跳到其他月份。
- Today 定位保持约 260ms 平滑滚动。
- `reduced-motion` 下立即定位。

## 13. 创建和编辑交互

### 13.1 工具栏

只保留：

```text
新建阶段
添加项目
添加批注
年 / 月 / 周 / 日
今天
```

Event、系统等可通过“添加”二级菜单或上下文入口创建。

### 13.2 添加阶段

- 默认开始日期为视口中心日期。
- 编辑名称、日期、描述、颜色、重要性和相关分类。
- 保存后立即显示阶段背景。

### 13.3 添加项目

- 先选择分类。
- 输入项目日期。
- 可选择父项目。
- 可选择子类型：阶段或并行方向。
- 保存后自动分轨。

### 13.4 添加批注

支持两种方式：

1. 单击某一天，创建单日批注。
2. 在日期刻度或画布空白处纵向拖动，创建范围批注。

拖动时：

- 显示临时大括号。
- 浮层显示开始、结束和持续天数。
- 松开后打开批注编辑器。
- 移动小于 5px 时按单日处理。

编辑字段：

- 标题
- 正文
- 开始日期
- 结束日期
- 关联分类
- 关联项目
- 关联阶段
- 心情
- 重要性

### 13.5 编辑区间

选中批注后，大括号顶部和底部出现调整手柄。

拖动手柄只能改变日期，不直接改变像素位置。最终日期通过 `worldYToDate()` 计算。

## 14. 选择与详情工作台

需要将选中状态统一为：

```ts
selectedEntity:
  | { type: 'stage'; id: string }
  | { type: 'project'; id: string }
  | { type: 'system'; id: string }
  | { type: 'event'; id: string }
  | { type: 'annotation'; id: string }
  | null
```

行为：

- 点击 Stage：打开阶段工作台。
- 点击 Project：打开项目详情。
- 点击 Annotation：打开批注编辑器。
- 点击 Event：打开事件详情。
- 点击空白或 Esc：关闭。
- 滚动不关闭选择。

现有 `StageWorkspace.tsx` 可以继续复用，但桌面上应作为覆盖式右侧抽屉打开。

因为右侧本身已经有批注栏，不能同时再挤出第二个固定栏。关闭详情抽屉后恢复批注栏。

## 15. 多端策略

### ≥1180px

- 日期刻度固定。
- 三分类并列。
- 批注栏固定在右侧。
- 详情工作台覆盖批注栏。

### 760–1179px

- 日期刻度固定。

## 16. 性能与窗口化

所有实体仅渲染：

```text
当前视口
+ 上方一屏
+ 下方一屏
```

性能规则：

1. Stage 背景可以绘制较大范围。
2. Project、Event、Annotation 正文必须窗口化。
3. 滚动过程中不重新计算完整布局。
4. 使用 `requestAnimationFrame` 更新可见窗口。
5. 几何和选择器使用纯函数与 memo。
6. 正文层使用 HTML。
7. 大括号、Today、连接线使用 SVG。
8. 不可见批注不创建 DOM。
9. 相同日期事件和批注预先聚合。
10. 轨道分配只在数据或缩放改变时重算。

性能数据集：

| 数据规模 | 目标 |
|---|---|
| 10 年、100 Stage、300 Project、500 Annotation | 平滑滚动 |
| 20 年、500 Project、1000 Annotation | 无明显交互阻塞 |
| 50 年、2000 Annotation | DOM 数量随视口变化 |

## 20. 最终完成标准

v14 完成时，用户必须能够：

1. 沿统一纵向时间理解过去、今天和未来。
2. 一眼识别当前人生阶段。
3. 同时查看学习、工作、生活的并行情况。
4. 查看考研政治、英语、专业课的真实开始和结束日期。
5. 通过 Today 横线知道当天哪些项目正在进行。
6. 使用大括号标注一天或连续几天。
7. 在大括号旁写一至多段文字。
8. 清楚区分两条日期重叠的批注。
9. 在批注密集时使用 `+N` 查看剩余内容。
10. 点击 Stage、Project、Event、Annotation 进入对应详情。
11. 编辑或删除 Stage 而不损坏项目与批注。
12. 在长时间跨度和大量数据下保持稳定流畅。

最终视觉感受应是：

> 远看是人生阶段，中距离看见不同领域和项目，靠近后可以读到某一天、某几天发生的真实故事。

## 21. 设计参考对应关系

最新“时间手稿 2.1”示范图中的视觉元素应按以下语义实现：

| 示范图元素 | 产品语义 |
|---|---|
| 左侧日历刻度 | 唯一真实时间坐标 |
| 紫色大范围边框 | 当前或主要 Stage |
| 绿色内缩边框 | 重叠 Stage |
| 学习、工作、生活 | 固定主分类栏目 |
| 政治、英语、专业课纵向胶囊 | 并行项目单元，纵向长度表示真实日期 |
| Today 横线 | 当前日期，穿过当日活跃内容 |
| 黄色菱形 | 单日 Event |
| 右侧大括号 | 单日或区间 Annotation |
| 并列大括号 | 日期重叠后的批注轨道 |
| `+N 条批注` | 超出直显容量的聚合入口 |

此文档为产品和工程实施基线。正式编码前若需要修改时间方向、实体语义或主分类数量，必须先更新本方案，再进入实现。
